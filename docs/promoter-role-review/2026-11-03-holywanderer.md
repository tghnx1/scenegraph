# Проверка классификации и рекомендаций Holywanderer

Среда: локальная копия базы, артист 2178 (Holywanderer), модель и конфигурация из локального окружения, классификатор `promoter-role-v7`. Production не изменялся.

## Независимая выборка

До обращения к модели был зафиксирован [порядок отбора 25 ранее не классифицированных событий](independent-selection-20261103.json). Из страниц RA независимо размечены 10 связей с явно названными организаторами; [файл меток](../../backend/tests/fixtures/promoter_role_independent_20261103.json) сохранён до запуска модели. Результат run 14: 10 из 10 обнаружены. Отрицательных меток в нём нет, поэтому оценить точность и признать критерий 80% пройденным по этому набору нельзя.

Отдельно [зафиксирован условный тест](../../backend/tests/fixtures/promoter_role_independent_policy_20261103.json): те же 10 подтверждённых положительных связей плюс пять площадок без явного подтверждения роли организатора. Эти пять — применение согласованного правила исключения, а не доказательство того, что площадка фактически не участвовала в организации. Первоначальный run 16 дал 3 корректных исключения и 2 ошибки формата. В отдельном повторе run 17 обе ошибки обработаны, и все пять профилей получили роль площадки. После повтора условный результат — 10 TP, 5 TN, 0 FP, 0 FN; precision и recall равны 100% для этого узкого условного набора. Два повтора и исходные ошибки нельзя скрывать. Выборка мала, ограничена событиями с несколькими RA-профилями и не является представительными независимыми отрицательными метками. `release_ready=false`.

## Сравнение выдачи после backfill

По сохранённым usage записано 43 714 входных и 25 537 выходных токенов; это не оценка расхода полной базы. Дополнительно к этому перед сравнением были классифицированы пять событий для независимых положительных меток.

Сравнение демонстрирует работу механизма, а не итоговое качество: классифицирована небольшая и целенаправленно выбранная часть графа, пять событий не обработаны. Исчезновение конкретного профиля из первой десятки может быть связано с неполным покрытием и изменением ранжирования. Например, в локальных данных у 8MM 53 события, из них текущей версией на момент проверки классифицированы 7; по ним одна связь `both` и шесть `unknown`. Делать вывод, что 8MM никогда не является организатором, нельзя. В новой выдаче OYE Records, CURA Berlin, Muster Label и Spinning Grounds связаны с одним событием из проверенных независимых положительных меток, поэтому результаты не следует считать независимым замером качества рекомендаций.

Production rollout не включён: нужны более широкая репрезентативная разметка по принятому правилу, устранение ошибок обработки и сравнение на более полном графе.

## Дополнительная обработка

Пользователь уточнил правило: совпадающая с площадкой сущность исключается из рекомендаций при отсутствии подтверждённого организаторского кредита. Отрицательная метка по этому правилу обозначает ожидаемое поведение продукта и сама по себе не доказывает фактическое отсутствие участия площадки в организации.

Пять ошибок run 15 повторно обработаны в локальном run 18: 5/5 успешно. В повторный запрос добавлена безопасная подсказка для неподтверждённых кандидатов. Отдельный run 19 обработал ещё 35 ранее неклассифицированных событий по исходным десяти профилям, исключив обе независимые выборки: 34 успешно, одно с ошибкой формата ответа. Ошибка отправлена на отдельный повтор; успех повтора не означает, что формат ответа всегда корректен.

После run 19, до классификации новых контрольных событий, shadow для 2178 вернул: K3LLR, RITMO3000, LMNTL, Diskolusion, ELM STREET 42, Dada, TraumburgFestival, xcuse:u, OYE Records, CURA Berlin. По сравнению с предыдущим shadow RITMO3000 и Diskolusion вошли в десятку, Muster Label и Spinning Grounds вышли. Это сравнение ограничено целевой выборкой событий, а не всей базой; изменения ранжирования сами по себе не доказывают роль конкретного профиля.

До нового обращения к модели отдельно зафиксированы [выборка 30 событий](independent-broad-selection-20261103.json) и разметка восьми связей в трёх манифестах `promoter_role_broad*_20261103.json`. Run 20 обработал семь из этих восьми событий; событие 2400151 осталось недоступным из-за ошибочной структуры двух ответов. По семи доступным связям: 2 TP, 5 TN, 0 FP, 0 FN; precision и recall по доступным меткам 100%, но одна связь недоступна, разметка частичная и выборка ограничена ранее неклассифицированными событиями с RA-профилями. Поэтому порог для rollout не подтверждён и `release_ready=false`. Попытка повтора ещё одного события из run 19 (10837) снова закончилась неподтверждённым именем кандидата. Ошибки требуют дальнейшей диагностики, а не считаются правильной классификацией.

Ещё два случая из той же выборки размечены и закоммичены до их классификации в run 21; оба профиля площадок исключены согласно разметке. Всего по новому частичному набору: 2 TP, 7 TN, 0 FP, 0 FN, 1 недоступный результат. Вывод о недостаточности выборки и незавершённом quality gate сохраняется. GitHub CI для commit `ac21500f`: backend 556 passed, 2 skipped, 5 warnings; frontend и production compose прошли, deploy пропущен. Локальный полный pytest с реальными переменными `.env` и заполненной копией базы дал 546 passed и 14 failed; это не конфигурация CI. Профильные тесты после завершения backfill: 85 passed.

## Версия v8

В v7 защита от ошибочного присвоения роли организатора площадке сравнивала имена после удаления пунктуации, но не распознавала `Renate Club` и `Renate`. В v8 отдельное слово `club` в начале или конце имени учитывается как вариант написания. Обычное слово, содержащее эти буквы, автоматически не объединяется. Для совпадающего профиля без подтверждения организаторской роли результат исключается из рекомендаций; явный организаторский кредит допускается. Новая версия требует независимого повторного измерения: результаты v7 нельзя считать результатами v8.

В контрольном run 23 версии v8: 10 TP, 6 TN, 0 FP, 2 FN и 2 недоступные связи. На доступных метках precision 100%, recall 83,3%; набор частичный, и недоступные случаи блокируют rollout. У одного ложно исключённого профиля `OYE Records` цитата содержала `hosted by OYE Records`, которую проверка v8 не принимала как явный кредит. Нельзя установить по сохранённым данным, сама ли модель вернула `unknown` или проверка понизила роль. Версия v9 также принимает формулировку `hosted by` и аналогичные явные кредиты; run 25 повторно измеряет её на контрольных событиях, run 26 ожидает завершения run 25 и пересчитывает 84 события для локального сравнения рекомендаций. Прерванный run 24 относится к v8 и не используется для оценки v9.

Run 25 версии v9: 12 событий обработаны, 3 отклонены валидатором. По проверенным 20 связям: 11 TP, 6 TN, 0 FP, 0 FN и 3 недоступных результата. Precision и recall для 17 доступных меток составили 100%, но эти результаты не проходят gate из-за недоступных связей и нерепрезентативной частичной разметки. `OYE Records` на этот раз сохранён как соорганизатор. Отдельная безопасная диагностика одного сбоя подтвердила, что модель предложила кандидата без подтверждения именем в цитате. GitHub CI для кода `891447be`: 560 passed, 2 skipped, 5 warnings; frontend и проверка production compose прошли.

Run 26 v9: 79 из 84 событий обработаны, 5 отклонены валидатором. Повторный run 27 включил эти пять и три ошибки контрольного run 25: все восемь обработаны. После повтора на 20 ранее размеченных связях получено 12 TP, 8 TN, 0 FP и 0 FN, недоступных нет. На этом наборе precision и recall равны 100%, но 3 из 20 связей потребовали повторной обработки, набор ограничен 15 событиями и частичной разметкой двух заранее отобранных групп. Он недостаточен для утверждения о качестве на всей базе; `release_ready=false`.

До run 27 результат shadow для 2178: K3LLR, LMNTL, Diskolusion, RITMO3000, ELM STREET 42, Dada, TraumburgFestival, xcuse:u, OYE Records, CURA Berlin. После run 27: K3LLR, LMNTL, Diskolusion, ELM STREET 42, Dada, TraumburgFestival, xcuse:u, OYE Records, CURA Berlin, Muster Label. Изменение ранжирования само по себе не является доказательством роли профилей; повтор включал три контрольных события, что влияет на независимость сравнения. Без выполнения полного backfill эти списки нельзя считать окончательной выдачей.

Сохранённый usage по run 25: 11 507 входных и 10 666 выходных токенов; по run 26: 66 079 входных и 34 470 выходных токенов, но для двух событий usage отсутствует. Повторный run 27: 7 336 входных и 4 812 выходных токенов. Это расход конкретной локальной проверки, а не оценка всей базы.
